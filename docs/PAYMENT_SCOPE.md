# 支付测算口径说明

[English](PAYMENT_SCOPE.en.md)

## 结论

**本仓库不提供、也不打算提供「输入病案 → 输出报销金额 / 支付额」的功能。** 这不是功能缺失，而是由 DIP 支付机制决定的边界。把它做成实时计算，会被判定为不懂业务。

## 依据

### 1. 官方 3.0 附件不含分值 / 点数

经逐表实测，国家医保局公开的《按病种分值（DIP）付费 3.0 版分组方案》xlsx 共 10 张工作表，**全表无「分值」或「点数」列**。附件给的是病种目录与入组规则，不是支付标准。

- 国家层面的分组方案定义「病种如何形成、如何入组」；
- 各病种的分值由各统筹区依据本地历史费用数据测算，属于地方参数；
- 因此任何声称「从国家表直接算出分值」的实现，都必然是在硬编码或编造地方参数。

本仓库把分值设计为**外部可插拔参数**：`extract.py` 只做格式转换与索引，不生成、不推断分值。

### 2. 点值必须等年终清算

DIP 的点值（每分对应的基金金额）在机制上等于：

```
点值 = 可用于 DIP 结算的基金总额 ÷ 统筹区内所有病例的总分值
```

分子（基金总额）与分母（全年总分值）都要在**结算年度结束后**才能确定。年内任何时点：

- 全年病例总量未知，总分值未知；
- 基金实际支出、调整项、结余留用 / 超支分担的清算结果未定；
- 因此点值只能事后清算，不存在「实时点值」。

年内可做的是**参数化测算**：在给定一个假设点值（或历史点值区间）的前提下做敏感性分析，且必须显式标注为测算值、非结算结果、不构成支付意见。

### 3. 入组不等于结算

一个病例入组之后，实际支付额还可能受以下因素影响，均不在国家分组方案附件范围内：

- 统筹区年度分值表与点值；
- 高低倍率病例、特病单议、歧义组（QY）等特殊规则；
- 结余留用、超支分担、质量考核等清算调整；
- 起付线、封顶线、自费项目、参保类型等参保待遇规则。

因此「入组结果」与「报销金额」之间不是一步映射。本仓库止于入组规则与口径的结构化，不进入支付金额计算。

## 本仓库明确不做的事

1. 不接收、不存储、不处理任何真实病案数据（含姓名、就诊记录、费用明细）；
2. 不内置任何分值表或点值，不以历史数据反推并当作现行标准；
3. 不输出「可报多少钱」「能报销多少」一类结论；
4. 不将测算结果表述为医保经办机构的认定结果；
5. 不声称获得任何官方认证或与发布机构存在隶属、授权关系。

## 若后续要做测算器

允许的形态是**参数化敏感性测算工具**，且需满足：

- 所有分值与点值由使用者显式传入，附来源与适用年度；
- 输出标注「测算值 · 非结算结果 · 以医保经办机构最终认定为准」；
- 不进入判定链路：测算属于下游分析，不影响规则库解析与 23 条断言的结果；
- 与 `DATA_NOTICE.md` 的数据权利边界一致：官方数据及其派生结果不因测算功能而获得再授权。
